# WXRImport

WordPressのデータをa-blog cmsに包括的に移行するための拡張アプリです。

## 概要

WordPress標準のエクスポート機能（WXR形式）を利用して、エントリー・メディア・カテゴリーを自動移行します。従来のa-blog cms標準移行機能では対応できないメディアファイルの移行も含む、完全な移行ソリューションを提供します。

## 主要機能

- **WXRファイル解析**: WordPress標準エクスポート（WXR 1.2形式）の自動解析
- **エントリー移行**: 投稿・固定ページ・カスタムフィールドの移行
- **メディア移行**: WordPressメディアファイルの自動ダウンロード・登録
- **アイキャッチ画像の引き継ぎ**: WordPressのアイキャッチ画像をa-blog cmsのメイン画像として自動設定
- **ブロック変換**: WordPressブロックをa-blog cmsブロック形式に自動変換
- **URL書き換え**: 本文内メディアURLの自動置換
- **カテゴリー移行**: WordPressカテゴリーの自動作成・マッピング
- **タグ移行**: WordPressタグの自動作成・関連付け
- **リアルタイム進捗**: 移行処理の進捗をリアルタイムで表示
- **バッチ処理**: 大量データ対応の最適化処理

## 動作環境

- **a-blog cms**: >= Ver.3.2.20
- **PHP**: >= 8.1

### 推奨環境

- **メモリ**: 512MB以上
- **実行時間制限**: 無制限または十分な時間設定
- **ネットワーク**: WordPressサイトへの安定した接続

## インストール方法

拡張アプリをダウンロード後、zipファイルを解凍して `extension/plugins/` に設置します。

設置が完了すると、「管理画面 > 拡張アプリ」に `WXRImport` という名前で本拡張アプリが表示されるので、インストールをクリックしインストールします。

## 使用方法

### 1. WordPressからエクスポート

WordPress管理画面で以下の手順を実行：

1. 「ツール > エクスポート」にアクセス
2. **「全てのコンテンツ」を選択**（重要）
3. 「エクスポートファイルをダウンロード」をクリック

⚠️ **注意**: 投稿のみのエクスポートではメディア情報が不完全となるため、必ず「全てのコンテンツ」を選択してください。

### 2. a-blog cmsで移行実行

1. a-blog cms管理画面の「WordPress移行プラグイン」にアクセス
2. WXRファイルをアップロード（ドラッグ&ドロップ対応）
3. 移行設定を選択：
   - ☑ メディアファイルを移行する
   - ☑ 本文内URLを自動書き換え
   - ☑ カテゴリーを自動作成
4. 「移行開始」をクリック

### 3. 進捗確認

- リアルタイムで進捗状況を確認
- エラーが発生した場合は詳細ログを表示
- 完了後に移行結果レポートを表示

## インポートの挙動

- インポート先は現在のブログです
- 全エントリーの投稿者は実行したログインユーザーになります（WordPress側の投稿者は引き継がれません）
- WordPressのパスワード保護設定は無視されます
- WordPressのカテゴリー階層は維持されます
- WordPressのアイキャッチ画像はa-blog cmsのメイン画像として引き継がれます
- Yoast SEOのメタ情報（タイトル・ディスクリプション）は引き継がれます
- WordPressのカスタムフィールドはa-blog cms側にも引き継がれます
- 本文中のWordPress画像・ファイルブロックはa-blog cmsのブロック形式に変換され、その他のブロックはHTMLとしてそのまま保存されます

## 自動付与されるカスタムフィールド

WordPress側の情報を引き継ぐため、各エントリーには以下のカスタムフィールドが自動で付与されます。WordPress側のデータとの突き合わせや、テンプレートでの参照に利用できます。

| フィールド名 | 内容 |
| --- | --- |
| `wp_post_id` | WordPressの投稿ID |
| `wp_guid` | WordPressのGUID |
| `wp_post_type` | WordPressの投稿タイプ（`post` / `page` など） |
| `wp_featured_media_id` | WordPressのアイキャッチ画像の投稿ID（アイキャッチが設定されている場合のみ） |

また、WordPressに設定されていたカスタムフィールドは、フィールド名の先頭に `wp_` を付けた名前でa-blog cms側に保存されます（例: `featured_image` → `wp_featured_image`）。

## 再実行時の注意

- 同じWXRファイルを再度インポートすると、エントリーは重複して作成されます
- メディアとカテゴリーは既存のものがあれば再利用されます
- 移行中は、同時に別の移行を開始できません（ロックされます）

## Tips

### メディアをHTTPダウンロードせずに移行する

WXRファイル内のメディアURLを**ローカルパスに書き換えておくと、HTTPダウンロードではなくサーバー上のファイルから直接コピー**してメディアを登録します。
移行元のWordPressサイトが既に停止している場合や、大量メディアでネットワーク経由のダウンロードを避けたい場合に有効です。

**手順:**

1. WordPressのアップロードディレクトリ（`wp-content/uploads/`）一式を、a-blog cmsが稼働しているサーバーに配置する
2. WXRファイル（XML）をVSCodeなどで開き、メディアURLのドメイン部分を一括置換する
   例: `https://example.com/wp-content/uploads/` → `/wp-content/uploads/`
   （添付ファイル情報だけでなく、本文中のメディアURLも含めてすべて置換してください）
3. 書き換えたWXRファイルをアップロードして移行を実行する

**置換後に使えるパス形式:**

- ドキュメントルート相対パス（例: `/wp-content/uploads/2026/01/sample.png`）
- 絶対パス（例: `/var/www/html/uploads/2026/01/sample.png`）

公開ディレクトリにアップロードファイルを置く場合は、a-blog cmsの管理画面以外からアクセスできないよう、配置場所のアクセス制御に注意してください。

## 設定階層

本プラグインの設定値は、意味（性格）に応じて 3 層に分けて配置しています。

| 層 | API | 寿命 | 例 |
|----|-----|------|-----|
| `.env`（`ablogcms/.env`） | `env('KEY', default)` | デプロイ単位 | パス、許可ホスト、サイズ上限、各種ポーズ |
| DB コンフィグ | `config('key', default)` | ブログ単位 | （現在未使用） |
| 管理画面フォーム | `$this->Post->get('key')` | 1 リクエスト | メディア取得・カテゴリ作成・タグ作成の業務判断 |

考え方:

- **「環境ごとに変わる」「画面から触らせたくない」「セキュリティに直結する」**設定は `.env`
- **「今回どう取り込むか」**の業務判断は管理画面フォーム

### 利用可能な `.env` キー

プロジェクトルートの [`.env.example`](.env.example) を参照してください。
全キーは省略可能で、省略時は安全側のデフォルトが適用されます。

主なキー:

| キー | 意味 | デフォルト |
|------|------|-----------|
| `WXR_IMPORT_LOCAL_PATH_BASE` | ローカル取り込みの許可ベース | `archives/wxr-import/source/` |
| `WXR_IMPORT_ALLOWED_PRIVATE_HOSTS` | 開発環境用に許可するプライベートホスト名 | 空（厳格にブロック） |
| `WXR_IMPORT_MAX_FILE_SIZE` | メディア最大サイズ（バイト） | `52428800`（50MB） |
| `WXR_IMPORT_DOWNLOAD_DELAY_MICROSECONDS` | 同一ドメインへの連続 DL 間隔 | `500000`（0.5 秒） |
| `WXR_IMPORT_BATCH_PAUSE_MICROSECONDS` | エントリーバッチ間のポーズ | `0`（無効） |
| `WXR_IMPORT_DEFAULT_BATCH_SIZE` | バッチサイズの既定値 | `50` |

`WXR_IMPORT_ALLOWED_PRIVATE_HOSTS` は **SSRF 防御を緩める設定** のため、本番環境では空欄のままにしてください。開発環境で Docker 内部の `host.docker.internal` 等を取り込みたい場合のみ設定します。

## トラブルシューティング

### よくある問題

**Q: メディアダウンロードが失敗する**
- WordPressサイトが稼働中であることを確認
- URLの形式が正しいことを確認
- ネットワーク接続を確認

**Q: メモリ不足エラーが発生する**
- バッチサイズを小さく設定（10-20件）
- PHPメモリ制限を増加
- 分割して移行を実行

**Q: 処理が途中で停止する**
- PHP実行時間制限を確認
- サーバーリソースを確認
- エラーログで詳細を確認
